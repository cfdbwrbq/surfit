Типы данных
===========

Задача — это набор именованных объектов (точки, кривые, изолинии, площади,
поверхности, маски, гистограммы и ЦМР), которые решаются на одной сетке. Эта
страница — справочник по типам: что это, как загружается и какие правила его
принимают. Синтаксис команд — в :doc:`commands`; как правила объединяются — в
:doc:`how_it_works`.

.. list-table::
   :header-rows: 1
   :widths: 15 26 37 22

   * - Тип
     - Что это
     - Чем загружается
     - Семейство правил
   * - points
     - нерегулярные XYZ-отсчёты
     - ``read_points``, ``pnts_load``, ``pnts_load_shp``
     - ``points``, ``points_leq``, ``points_geq``
   * - curves
     - 2D-полилиния
     - ``read_curves``, ``curv_load``, ``curv_load_bln``, ``curv_load_shp``
     - ``curve``, ``curve_leq``, ``curve_geq``, ``fault``
   * - contours
     - 3D-полилиния; Z — часть данных
     - ``read_contours``, ``cntr_load``, ``cntr_load_bln``, ``cntr_load_shp``
     - ``contour``, ``contour_leq``, ``contour_geq``
   * - areas
     - полигон
     - ``read_areas``, ``area_load``, ``area_load_bln``, ``area_load_shp``
     - ``area``, ``area_leq``, ``area_geq``, ``area_mean``, ``area_wmean``, ``area_surf``
   * - surfaces
     - регулярная сетка значений Z
     - ``surf_load``, ``surf_load_grd``, ``add_surface``

   * - masks
     - логическая сетка

   * - grid
     - ячейки, на которых решается задача
     - ``grid``, ``grid_auto``, ``grid_get``, ``grid_get2``
     - не правило
   * - histograms
     - распределение значений
     - ``hist_read``, ``hist_from_surf``, ``hist_from_pnts``

     - геопривязанный растр из ``globe``

Точки
-----

Нерегулярные XYZ-отсчёты. Правило ``points`` проводит поверхность через них,
``points_add`` приближает их с весом, а ``points_leq`` и ``points_geq``
превращают измеренные значения в границы.

.. code-block:: python

   task.read_points("wells.txt", "wells")
   task.points("wells")

Файл точек — колоночный текст; ``col1``..``col4``, разделитель и число строк
заголовка — аргументы. ``points_add`` нужен, когда измерения шумные и
поверхность должна приближать, а не интерполировать.

Кривые
------

2D-полилиния. Сама линия значения не несёт, поэтому его задаёт правило:
``task.curve(10, "iso1")`` делает поверхность равной 10 вдоль ``iso1``.
``curve_leq`` и ``curve_geq`` превращают это в границу, а ``curve_surf`` берёт
значение из другой поверхности вместо константы.

.. code-block:: python

   task.read_curves("iso1.xy", "iso1")
   task.curve(10, "iso1")

Те же данные с правилом ``fault`` — линия, через которую поверхность может
скачком меняться. Разлом не добавляет данных; он меняет связь соседних ячеек.

Изолинии
--------

3D-полилиния: у каждого узла есть x, y и z, и z — измеренное значение. Поэтому
правила изолиний не принимают значения: ``contour`` интерполирует значения
вдоль линии, а ``contour_leq`` / ``contour_geq`` используют их как границы.

.. code-block:: python

   task.read_contours("isolines.xyz", "iso")
   task.contour("iso")

Изолиния — естественный вход для оцифрованной карты: значение известно на
линии, а пространство между линиями заполняет ``completer``.

Площади
-------

Полигон. ``area`` задаёт постоянное значение внутри, ``area_mean`` и
``area_wmean`` — среднее, ``area_surf`` заставляет поверхность следовать другой
поверхности там, а ``area_completer`` применяет сглаживание только внутри
полигона. Значение ``undef`` исключает площадь из результата.

.. code-block:: python

   task.read_areas("zone.txt", "zone")
   task.area(10, "zone")

Поверхности
-----------

Регулярная сетка значений Z. Результат каждой задачи — поверхность, и
поверхность может быть входом: из родного формата, из сеточного формата или
массивом numpy. ``add_surface`` принимает массив, начало и шаг его сетки.

.. code-block:: python

   task.surf_load("regional.dat", "regional")
   task.surface("regional")

Форма с массивом описана в :doc:`python`; это кратчайший путь от сетки модели к
тренд-поверхности.

Маски
-----

Сетка истинных и ложных значений. Это не поверхность: маска ограничивает
другое правило истинными ячейками. Варианты — ``mask``, ``mask_leq``,
``mask_geq``, ``mask_mean``, ``mask_wmean`` и ``mask_surf``; ``mask`` со
значением ``undef`` вырезает дырку в результате.

.. code-block:: python

   task.mask_load("mask.mask", "limit")
   task.mask("undef", "limit")

Маски читаются из родного файла и сохраняются как сетка Surfer
(``mask_save_grd``) или xyz (``mask_save_xyz``).

Сетка
-----

Набор ячеек, на которых определено каждое правило. У задачи она одна. ``grid``
создаёт явную сетку, ``grid_auto`` подгоняет её под загруженные данные (команда
Tcl ``grid``), ``grid_get2`` округляет число узлов вверх до степеней двойки, а
``grid_get_for_pnts`` подгоняет под набор точек. Сетку можно сохранить и
загрузить отдельно или хранить вместе с задачей.

.. code-block:: python

   task.grid(-10, 10, 0.25, -10, 10, 0.25)

Гистограммы
-----------

Распределение значений. ``hist_read`` читает его из колоночного текста с
диапазоном значений, ``hist_from_surf`` и ``hist_from_pnts`` строят по данным, а
``hist_write`` сохраняет. Правило ``hist`` подстраивает поверхность так, чтобы её
гистограмма совпала. Гистограммы — часть родного файла задачи, поэтому
``file_save`` и ``file_load`` хранят их вместе с остальным.

.. code-block:: python

   task.hist_read("eq10.txt", 10, 40)
   task.hist("*")

Цифровые модели рельефа
-----------------------

ЦМР приходит из библиотеки ``globe``: это растр с геопривязкой, поэтому его
можно спроецировать на сетку задачи. ``dem`` заставляет поверхность следовать
ему, ``dem_add`` добавляет его с весом. Модель можно разложить на более грубые
уровни и собрать обратно: ``dem_decomp`` добавляет следующий грубый уровень,
``dem_recons`` делает шаг назад, ``dem_full_recons`` возвращает исходную.
Уровни хранятся, поэтому исходные значения возвращаются точно.

.. code-block:: python

   task.dem_load_hgt("N00E006.hgt")
   task.dem("N00E006.hgt")

Загрузчики ЦМР принимают шаблон файлов, а не один путь, а ``dem_load_hgt_zip``
требует zlib (сборка CMake включает его, если находит). ЦМР принадлежат задаче:
у каждой сессии свой контейнер, поэтому две задачи могут загрузить разные растры
под одним именем, а вызовы уровня модуля используют контейнер библиотеки;
подробности — в :doc:`python`. :doc:`terrain` читает тайл SRTM в обоих
фронтендах и показывает, что дают оба правила.

Что у них общего
----------------

* У каждого объекта есть имя, и любая команда выбирает объекты по shell-шаблону;
  ``"*"`` — значение по умолчанию, поэтому ``task.points()`` берёт все точки в
  памяти.
* У большинства семейств правил три варианта: обычная команда добавляет
  правило, ``_add`` добавляет его с весом, а ``_leq`` / ``_geq`` превращают в
  неравенство.
* Каждое правило возвращает по флагу на каждый совпавший объект; ``[False]``
  означает, что шаблон ничего не нашёл.
* Порядок добавления правил — их приоритет; :doc:`how_it_works` описывает, что
  с этим порядком делает решатель.
* Результат — поверхность с именем ``map_name``. ``file_save`` хранит всю
  задачу (данные, правила и результат), а ``surf_save`` — одну поверхность;
  список форматов — в :doc:`formats`.
