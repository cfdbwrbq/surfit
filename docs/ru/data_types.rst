Типы данных
===========

surfit работает с небольшим набором типов данных. Каждый объект задачи имеет
имя, лежит в памяти, выбирается шаблоном оболочки и записывается в родной файл
задачи; правило гриддинга называет тип, к которому относится. Эта страница
описывает типы и указывает семейства правил; все команды с аргументами — в
:doc:`commands`.

.. list-table::
   :header-rows: 1
   :widths: 15 26 37 22

   * - Тип
     - Что это
     - Чем читается
     - Семейство правил
   * - точки
     - нерегулярные XYZ-отсчёты
     - ``read_points``, ``pnts_load``, ``pnts_load_shp``
     - ``points``, ``points_leq``, ``points_geq``
   * - кривые
     - 2D-ломаная
     - ``read_curves``, ``curv_load``, ``curv_load_bln``, ``curv_load_shp``
     - ``curve``, ``curve_leq``, ``curve_geq``, ``fault``
   * - изолинии
     - 3D-ломаная; Z — часть данных
     - ``read_contours``, ``cntr_load``, ``cntr_load_bln``, ``cntr_load_shp``
     - ``contour``, ``contour_leq``, ``contour_geq``
   * - площади
     - полигон
     - ``read_areas``, ``area_load``, ``area_load_bln``, ``area_load_shp``
     - ``area``, ``area_leq``, ``area_geq``, ``area_mean``, ``area_wmean``, ``area_surf``
   * - поверхности
     - регулярная сетка значений Z
     - ``surf_load``, ``surf_load_grd``, ``add_surface``
     - ``surface``, ``surface_leq``, ``surface_geq``, ``trend``
   * - маски
     - логическая сетка
     - ``mask_load``
     - ``mask``, ``mask_leq``, ``mask_geq``, ``mask_mean``, ``mask_wmean``, ``mask_surf``
   * - сетка
     - ячейки, на которых решается задача
     - ``grid``, ``grid_auto``, ``grid_get``, ``grid_get2``
     - не правило
   * - гистограммы
     - распределение значений
     - ``hist_read``, ``hist_from_surf``, ``hist_from_pnts``
     - ``hist``
   * - DEM
     - геопривязанный растр из ``globe``
     - ``dem_load_hgt``, ``dem_load_grd``, ``dem_load_globe``, ``dem_load_dtm``
     - ``dem``, ``dem_add``

Точки
-----

С разрозненных отсчётов начинается большинство задач. Правило ``points``
проводит поверхность через них; ``points_add`` добавляет то же условие с весом,
а ``points_leq`` / ``points_geq`` превращают измеренные значения в границы:

.. code-block:: python

   task.read_points("wells.txt", "wells")
   task.points("wells")

Файл точек — текст с колонками; ``col1``..``col4``, разделитель и число строк
заголовка — аргументы. ``points_add`` нужно там, где измерения шумные и
поверхность должна приближать, а не интерполировать.

Кривые
------

Кривая — это 2D-ломаная: сама линия значения не несёт, его задаёт правило.
``curve 10 iso1`` означает, что вдоль ``iso1`` поверхность равна 10.
``curve_leq`` / ``curve_geq`` делают это границей, а ``curve_surf`` берёт
значение с другой поверхности вместо константы:

.. code-block:: python

   task.read_curves("iso1.xy", "iso1")
   task.curve(10, "iso1")

Те же данные с правилом ``fault`` — линия, через которую поверхность может
прыгнуть. Разрыв не добавляет данных: он меняет связь соседних ячеек.

Изолинии
--------

Изолиния — 3D-ломаная: у каждого узла есть x, y и z, и z — это измеренное
значение. Поэтому правилам изолиний не нужен аргумент значения: ``contour``
интерполирует значения вдоль линии, а ``contour_leq`` / ``contour_geq``
используют их как границы:

.. code-block:: python

   task.read_contours("isolines.xyz", "iso")
   task.contour("iso")

Изолиния — естественный вход для всего, что оцифровано с карты: линия — это
место, где значение известно, а пространство между линиями заполняет
``completer``.

Площади
-------

Площадь — это полигон. ``area`` задаёт внутри постоянное значение,
``area_mean`` / ``area_wmean`` — среднее, ``area_surf`` заставляет поверхность
следовать другой поверхности, а ``area_completer`` применяет сглаживание
только внутри полигона. Значение ``undef`` исключает площадь из результата:

.. code-block:: python

   task.read_areas("zone.txt", "zone")
   task.area(10, "zone")

Поверхности
-----------

Поверхность — регулярная сетка значений z. Результат каждой задачи — это
поверхность, и она же может быть входом: загруженная из родного формата, из
сеточного формата или переданная массивом numpy. ``add_surface`` принимает
массив вместе с началом и шагом его сетки:

.. code-block:: python

   task.surf_load("regional.dat", "regional")
   task.surface("regional")

Форма с массивом описана в :doc:`python`; это самый короткий путь от
модельной сетки к поверхности-тренду.

Маски
-----

Маска — сетка значений true и false. Это не поверхность: она ограничивает
другое правило истинными ячейками. Варианты — ``mask``, ``mask_leq``,
``mask_geq``, ``mask_mean``, ``mask_wmean`` и ``mask_surf``; ``mask`` со
значением ``undef`` вырезает в результате дыру:

.. code-block:: python

   task.mask_load("mask.mask", "limit")
   task.mask("undef", "limit")

Маски читаются из родного файла, а сохраняются в сетку Surfer
(``mask_save_grd``) или xyz (``mask_save_xyz``).

Сетка
-----

Сетка — набор ячеек, на которых определено каждое правило; у задачи она одна.
``grid`` создаёт явную сетку, ``grid_auto`` подгоняет её под загруженные данные
(Tcl-команда ``grid``), ``grid_get2`` округляет число узлов вверх до степеней
двойки, а ``grid_get_for_pnts`` подгоняет сетку под набор точек. Сетку можно
сохранить и загрузить отдельно или хранить вместе с задачей:

.. code-block:: python

   task.grid(-10, 10, 0.25, -10, 10, 0.25)

Гистограммы
-----------

Гистограмма — распределение значений. ``hist_read`` читает её из текстового
файла с колонками и диапазоном значений, ``hist_from_surf`` и
``hist_from_pnts`` строят её по данным, ``hist_write`` сохраняет. Правило
``hist`` подгоняет гистограмму поверхности под заданную. Гистограммы входят в
родной файл задачи, поэтому ``file_save`` и ``file_load`` сохраняют их вместе
со всей задачей:

.. code-block:: python

   task.hist_read("eq10.txt", 10, 40)
   task.hist("*")

Цифровые модели рельефа
-----------------------

DEM приходит из библиотеки ``globe``: это растр с геопривязкой, поэтому его
можно спроецировать на сетку задачи. ``dem`` заставляет поверхность следовать
ему, ``dem_add`` добавляет его с весом. Саму модель можно раскладывать на более
грубые уровни и восстанавливать: ``dem_decomp`` добавляет следующий уровень,
``dem_recons`` возвращает на один уровень назад, ``dem_full_recons`` — к
исходному. Уровни сохраняются, поэтому исходные значения возвращаются точно.

.. code-block:: python

   task.dem_load_hgt("N00E006.hgt")
   task.dem("N00E006.hgt")

Два замечания: загрузчики DEM принимают **шаблон** файла, а не один путь, и
``dem_load_hgt_zip`` требует zlib (сборка CMake включает его, если находит).
Кроме того, DEM живут
вне состояния сессии и общие для всех задач процесса; почему — объясняет
:doc:`python`.

Что у них общего
----------------

* У каждого объекта есть имя, и каждая команда выбирает объекты шаблоном
  оболочки; ``"*"`` — умолчание, поэтому ``task.points()`` берёт все точки в
  памяти.
* Каждое правило возвращает по флагу на найденный объект, а ``[False]``
  означает, что шаблон ни с чем не совпал.
* Порядок добавления правил — их приоритет; что с этим порядком делает
  решатель, описано в :doc:`how_it_works`.
* Результат — поверхность с именем ``map_name``. ``file_save`` сохраняет всю
  задачу — данные, правила и результат, — а ``surf_save`` одну поверхность;
  форматы перечислены в :doc:`formats`.

Это данные для пяти возможностей движка: несколько типов данных, правило
гриддинга на каждый набор, приоритеты между ними и правила для интерполяции,
приближения, неравенств и средних. Метод, который за ними стоит, — CMOFS
(:doc:`how_it_works`).
